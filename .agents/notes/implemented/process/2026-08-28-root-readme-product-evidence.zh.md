# Agent Note: 根 README 以产品证据为主线

Status: implemented

[English](2026-08-28-root-readme-product-evidence.md) | 中文

## 问题

根 README 先用一小段文字介绍桌面端与手机端，随后直接进入运行命令。它没有说明持久会话、插件组合和多种客户端为何属于同一个产品。读者无法从中区分仓库的产品方向与安装入口，页面也没有展示已经通过精确产品验收录屏证明的已交付行为。

架构参考负责内部组合方式，用户指南负责操作流程。把两者复制进 README 会拉长产品首页，还会为随运行时变化的事实建立第二个维护位置。

## 决策

根 README 是 DeepSeek Gestalt 与 DeepSeek Harness 的产品首页。它首先说明愿景：一个持久会话连接模型、工具、文件、人的决定和客户端，插件则让各项能力保持可替换。随后页面展示少量当前用户工作流，再列出已实现能力和最短的受支持运行方式。

每个嵌入的产品 GIF 都来自已合并改动所验收的真实产品路径，其 URL 使用不可变的仓库对象 id。选中的内容覆盖仓库 Workbench、持久 Side Chat 续接和加密 Mobile Companion 续接。README 只描述当前产品可见行为，或由所链接架构与用户参考文档负责的事实；详细来源依次保留在已合并的 PR（Pull Request）[#317](https://github.com/gestaltrun/deepseek-harness-gestalt/pull/317)、[#329](https://github.com/gestaltrun/deepseek-harness-gestalt/pull/329) 和 [#312](https://github.com/gestaltrun/deepseek-harness-gestalt/pull/312) 中。

安装步骤保持简短。README 将首次运行细节链接到用户指南，将组合方式和生命周期语义链接到架构文档，将当前运行时接口链接到生成目录，并将贡献者流程链接到开发文档。社区和法律信息放在产品与运行章节之后，仍然可以直接访问。

## 曾考虑的替代方案

**保留以命令开头的 README。** 不予采纳：只有安装方式无法解释产品，也无法说明 Desktop、Web、Mobile、会话和插件工作为何属于一个整体。

**列出所有包和功能。** 不予采纳：源码和生成目录已经负责完整清单，手工维护的列表会产生漂移。

**使用 mock 截图或概念图。** 不予采纳：它们无法证明当前产品行为。已验收的产品录屏可以提供具体证据，又不会把 README 变成测试报告。

**嵌入所有可用的产品 GIF。** 不予采纳：大量重复动画会拖慢页面，并遮蔽最能说明产品方向的三条工作流。

## 后果

新读者可以先理解产品，再选择安装路径，也可以不离开页面就查看真实工作流。README 会变长并下载三个小型 GIF，因此维护者限制其数量，且只用另一段已验收的产品录屏替换现有资源。详细行为、配置和验证仍由各自的权威文档与 PR 维护。
