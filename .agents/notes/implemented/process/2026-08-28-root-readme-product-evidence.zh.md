# Agent Note: 根 README 描绘獭子哥产品层

Status: implemented

[English](2026-08-28-root-readme-product-evidence.md) | 中文

## 问题

根 README 把獭子哥描述为桌面端与手机端工作空间，但没有准确说明它和 DeepSeek Harness 官方仓库的关系。读者无法看出哪些能力来自 DSH 基础、獭子哥增加了哪些产品功能、集成了哪些社区插件，以及哪些工作正在交付或仍处于计划阶段。

简短的演示集也遮蔽了已完成产品工作的广度。完整包清单则会产生相反问题：它会重复生成目录，并用实现结构代替产品说明。

## 决策

根 README 将獭子哥定义为官方 DSH 之上的产品层。产品方向包含四部分：补齐可安装产品、保持 DSH 组合方式与入口兼容、集成经过审阅的社区插件，以及让多个客户端共享一份持久权威。README 把上游兼容视为持续的仓库工作，不会声称开发者预览阶段的每个 commit 都可相互替换。

英文产品名是 **Gestalt**，中文产品名与 IP 角色是 **獭子哥**。产品首页保存并展示已经确认的角色设定图。现有包名、应用标识符、发行 tag 和历史引用保持不变，直到另一项协调重命名明确要求迁移。

仓库内成对的中英文 PNG 使用相同的嵌套方框布局，区分官方 DSH 基础、獭子哥共享产品层、三个产品域组、子产品域和具体产品功能。每张图片只使用一种语言，不放双语对照标签。`DONE` 要求能力已经合并进 `master`，但不表示它已包含在最新打包版本中。`DOING` 要求存在正在交付的改动。`TODO` 要求存在已经选入产品计划的开放 Issue。该地图介绍 DSH 基础周围增加的产品功能，不重复官方 DSH 的包目录和工具目录。

README 使用一张纵向表格同时承担产品状态清单和功能导览。独立的一级产品域与二级产品域列复用方框图中的工作体验域、客户端与交付域、扩展与协作域层级，不使用树形字符。每行写明完成度、具体用户行为，并且最多放一段产品录屏。已完成功能链接到所属产品文档，不把交付记录写成产品说明；计划中的功能链接定义方向的 tracker 条目。录屏覆盖 Workbench 与 Better Sidebar、Side Chat、Schedule、AI Browser、Workspace Reference、Annotation 和 Mobile Companion。每个嵌入的 GIF 都在 URL 中使用不可变的仓库对象 id。

安装步骤保持简短。README 将首次运行流程链接到用户指南，将组合方式和生命周期语义链接到架构与应用参考，将外部集成链接到插件目录，并将贡献者流程链接到开发文档。

## 曾考虑的替代方案

**只把獭子哥描述成另一个 DSH 客户端。** 不予采纳：Desktop、Mobile、Workbench、发行、验收和社区集成共同构成产品层，不是一项客户端实现。

**列出每个包和工具。** 不予采纳：生成目录和源码负责完整清单。产品地图按用户可见的结果组织獭子哥增量。

**只展示已完成工作。** 不予采纳：活跃产品方向仍会不可见。由 tracker 支撑的 `DOING` 和 `TODO` 可以区分已经承诺的交付与计划，又不会把开放工作写成已发布能力。

**使用 mock 截图或概念图。** 不予采纳：它们不展示用户可以运行的产品。产品录屏直接展示当前工作流。

**使用 Mermaid 绘制架构图。** 不予采纳：自动流式布局无法在不同 README 宽度下固定所需的嵌套方框层级。仓库内图片让中英文页面保持相同的视觉分组。

**把多段录屏并排放置。** 不予采纳：宽行会占据页面，在窄屏上也容易变得拥挤。表格每行只放一段录屏，保持纵向浏览。

## 后果

读者可以一次看清官方 DSH 基础、獭子哥共享产品层、产品域、完成度和具体功能。状态表可能产生漂移，因此每次涉及产品范围的 README 改动都要根据实时 tracker 检查正在交付和计划中的条目。README 不再用第二个路线图或功能画廊重复这张表。详细运行时行为、配置、兼容限制和验证仍由各自的权威文档与 PR 维护。
