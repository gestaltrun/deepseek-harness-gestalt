# DeepSeek Gestalt Mobile

English | [中文](README.zh.md)

Mobile account and Personal Pairing shell for the current Installation. Before GitHub authorization, it reads the native device name and iOS or Android platform through `@capacitor/device`, binds that presentation to the resulting Account Session, shows the bilingual retention notice, opens authorization outside the app, and polls Platform with P-256 proof. After sign-in, Mobile decodes the same complete endpoint-owned invitation from paste or browser-camera QR scanning, creates XKpsk3 messages 1 and 3 locally, displays words derived from the completed handshake hash, and polls the opaque mailbox until Desktop confirmation. Desktop creates one Mobile Relay credential and random 32-byte attachment key per Personal Pairing; Platform registers only credential digests and copies the authenticated Installation presentation. Mobile opens each Snow-sealed grant and attachment key into a versioned account-scoped protected document that rejects duplicate pairing ids and retains multiple independent pairings plus one explicit selection. Desktop names enter that document only after authenticated foreground synchronization. Selecting a Desktop drains the previous Relay, invalidates its channel and projection, persists and displays the new selection with its last-confirmed cache, and starts the selected grant's retrying attachment asynchronously; mutations remain disabled until authentication and synchronization. Unpair revokes and erases only the selected pairing, while sign-out and Account switching preserve isolated pairing documents.

The entry accepts one operated production identity through `VITE_PLATFORM_ORIGIN`, `VITE_PLATFORM_CALLBACK_URL`, `VITE_PLATFORM_GITHUB_CLIENT_ID`, `VITE_PLATFORM_CREDENTIAL_REFERENCE`, `VITE_PLATFORM_DATABASE_IDENTITY`, and `VITE_PLATFORM_IDENTITY_NAMESPACE`. Missing fields, localhost, non-HTTPS origins, and callback mismatch fail before local storage, rendering, or network traffic.

The shared Mobile entry includes the `@capacitor/browser` and `@capacitor/device` adapters. It calls the browser adapter directly from the prepared authorization button's user activation and has no `window.open`, popup, current-context navigation, or custom-URL token fallback. The Personal Pairing page races cancellation against pending `getUserMedia`, uses `@zxing/browser` for one QR value, and stops the decoder plus every current or late camera track after success, failure, cancellation, or unmount. Unsupported camera APIs, permission denial, missing cameras, empty results, malformed links, expiry, replay, and cross-account attempts fail explicitly; QR and paste never create separate invitation or handshake paths. `IndexedDbInstallationAccountStore` uses the selected database identity in its database name; native packaging supplies the stable WebView origin. Missing `crypto.randomUUID` fails before rendering because Installation id creation requires a secure browsing context.

## Shared Session presentation

The encrypted channel carries one JSON-only Mobile projection: conversations are arrays, turn indexes are entry arrays, and pending interactions contain only their id, Session id, kind, and domain payload. Before publication, the authenticated receiver validates every required conversation field and known node, Tool presentation, content, or pending-payload discriminant; a future node kind becomes the shared unknown-node carrier, while an unknown Tool card remains an extensible render intent and malformed known content is rejected. The local adapter then constructs the Client Runtime `SessionListState`, `WorkspaceView`, `ConversationSnapshot`, and `PendingWait` presentation carriers. Pending responders call the same generation-bound channel and return its accepted or rejected receipt to the shared Approval or Ask User owner; no Map, class, or callback crosses the wire.

The bundled Mobile entry keeps list/detail navigation in `apps/mobile` but defines neither a Mobile Session-summary model nor a Mobile conversation-node router. Session grouping and focusable keyboard rows execute the public `ui-workspace` presentation, while finalized conversation nodes execute the public `ui-conversation` keyed presentation. The full-screen detail root binds the shared content width, composer gutter, card width, and long-draft cap without mounting Desktop `ConversationRoot`. A subscribed clock updates shared relative-time labels. The tail history response replaces the authoritative conversation; `loadOlder` sends the oldest visible sequence and prepends a continuity-checked page. Locale and light/dark theme flow through the shared conversation, Tool, attachment, question, and Workspace implementations. Images render through `ImageGallery`; ordinary Tool names use the Desktop built-in keyed roster and unknown names alone use `GenericToolCard`. Mobile never mounts Desktop columns, Settings, model selection, plugin configuration, or terminal input.

The bundled-entry snapshot builds and loads `main.tsx`, resolving its `launchMobileProduct` dependency to an authenticated generation-bound fixture while the production resolver invokes only the operated start callback. At 390 px in English/dark and Chinese/light contexts it executes shared Markdown, code, image, known and unknown Tool, diff, Host error, future-node fallback, Approval, Ask User, and long composer content, including bounded scrolling and reachable actions. It adds no keyless product selection to `main.tsx`, runs no model round, and proves neither a live Desktop transport nor native WebView execution. `apps/mobile/prototype-companion` and development ports 5173/5174 are not Mobile product acceptance origins.

The shipped entry seals one versioned authenticated Workspace, Session, and transcript projection snapshot at rest per Paired Desktop with an HKDF-derived AES-GCM key owned by the Personal Pairing. The snapshot uses the `companionCacheDatabaseName` IndexedDB namespace (`${accountStorageNamespace(environment, accountId)}:companion-cache`), so account switch isolates cache and receipts from protected pairing authority. Mobile restores it only as read-only Remote Offline presentation, disables every mutation until foreground synchronization, and exposes per-Desktop cache clearing. Attachment bytes, terminal content, spill files, and credentials never enter the cache. `CompanionUncertainOperationSettlement` reserves a non-evictable `prepared` Operation Receipt before transmission and durably changes it to `unknown` immediately before the first Relay send attempt. A failure after that fence remains unknown until a single-flight `query-operation-status` reconciliation returns the authoritative result or explicit absence; Mobile never replays an operation.
The attachment controller reads the selected browser `File` bytes, erases its local copy after attachment-key encryption, uploads only ciphertext to the operated HTTPS `remote-attachments` route with current pairing-scoped authorization, validates the returned single-use capability, and hands only the bounded `offer-attachment` operation to the Encrypted Companion sender. A runtime-owned permit binds the whole asynchronous transfer to one physical connection generation; every external await and both upload and send require that generation to remain synchronized and foregrounded. The mutation channel returns the operation id and send completion to the Mobile surface, which correlates Desktop confirmation, attachment rejection, Host failure, and reconnect status without treating them as search results. A rejected attachment or Host failure becomes a visible alert. The surface owns exactly one unresolved attachment operation: while it is sending or uncertain, selecting another file fails before the channel runs; confirmation, rejection, failure, or reconciled status releases that operation id. If the sender rejects or resolves after that generation becomes invalid, `CompanionAttachmentDeliveryUncertainError` retains the operation id and the surface displays an uncertain state until `query-operation-status` resolves it. Mobile search sends the trimmed query to Desktop and displays every correlated authoritative Session id/snippet pair even when the Companion Cache lacks that Session; cached titles, Workspace labels, summaries, transcripts, and substring matches never label or create search hits. `operation-failed` preserves Host HTTP status, wire validation, business code/message, or timeout as a visible Mobile error.

## Known Limitations and Deferred Work

- The operated entry selects `SnowMobileHandshakeClient`, `SnowMobileAttachmentOwner`, and the foreground Relay lifecycle and has no keyless or development product selection. It requires `VITE_REMOTE_RELAY_WSS_URL`, `VITE_REMOTE_RELAY_ATTACH_TIMEOUT_MS`, `VITE_REMOTE_RELAY_HEARTBEAT_INTERVAL_MS`, `VITE_REMOTE_RELAY_RECONNECT_DELAY_MS`, `VITE_REMOTE_RELAY_INBOUND_MAX_BYTES`, and `VITE_REMOTE_RELAY_INBOUND_MAX_MESSAGES`, all validated before rendering. Every Relay ready or peer-update projection must name the current selected grant's pairing selector before key lookup or IK begins; a mismatch drops the product connection and mutation authority while retaining the selected Desktop's read-only cache. Matching credential-bound metadata starts one fresh IK attempt, and ciphertext cannot reach synchronization until the exact route, selector, Desktop/Mobile attachment ids, and generation finish that attempt.
- The encrypted projection cache, clear-cache UI, and Operation Receipt owner are wired. Session creation, prompt, cancel, interaction, and attachment mutations all use the same settlement path; recovered authoritative success, Host failure, and explicit absence update the correlated Mobile surface and trigger the required bounded refresh.
- The attachment-bound Snow channel owns decoded projections and results and is the only sender for Companion mutations. It atomically binds one physical generation's mutation and content adapters to `MobileCompanionSurface`; a receiver, pending responder, prompt confirmation, or channel from an earlier attachment cannot dispatch through its replacement. Companion major 3 carries authoritative Session and Workspace discovery, Workspace or Ungrouped Session creation, conversation history with real Host running state, awaited prompt submission, cancellation, Approval and Ask User settlement, and digest-verified historical-image bytes into the shared Web presentation. Correlated failures reject pending work and remain visible; confirmed mutations trigger a bounded history and list refresh.
- `CompanionForegroundRuntime` is the sole Relay start/stop owner. A selection change invalidates mutation authority, releases the prior pairing's projection and Relay, binds the new selection's read-only cache, and lets only its persisted grant retry attachment; it never merges Session state across Desktops or falls back automatically. Backgrounding stops WSS, and successful selected-Desktop `unpair()` drops that grant so a later visibility change cannot start its socket while retaining every other pairing. Every physical attachment ready/lost transition creates or invalidates one synchronization generation, and transport errors also clear `socketOpen` and `synchronized`. The Mobile entry renders no invented Desktop name, fixed offline state, Device Principal, or local Session before authenticated synchronization. Attachment work uses a current-generation mutation permit, uploads only ciphertext, and sends the returned capability through the encrypted channel; search results and Host failures come only from correlated Desktop results. Previously authenticated content may remain visible across a reconnect, but Session mutations, search, and attachment controls stay disabled until current-generation resynchronization. Mobile ships no background notification delivery; opening or foregrounding the application is how it learns current Desktop state.
- Release acceptance runs the exact checked-in Snow JS/WASM package on Node 22 and 24, iOS Simulator WKWebView, and Android Emulator WebView. The native WebView runners cover pairing, reconnect, fresh ephemeral keys, bidirectional transport, tamper, replay, ordering, cross-pairing, and maximum frame limits; local Vite and `prototype-companion` are not evidence for this product path.
- `apps/mobile/ios` and `apps/mobile/android` are the checked-in Capacitor release projects for `com.alibaba.gestalt.mobile`. Their custom protected-storage plugins, native file-input picker, camera permissions, `@capacitor/app` lifecycle, App Store export, and release-key APK flow are part of this shell. The complete one-time pairing invitation enters only through in-app QR scanning or paste; the native projects register no interceptable custom URL scheme.
