# Agent Note: 项目成员权威数据与 Platform 身份存储同级共存

Status: implemented

[English](2026-08-27-project-membership-core.md) | 中文

## 问题

协作规格（#338）引入了云端项目的 owner/admin/member 角色、项目自定义功能标签，以及接受即原子链接工作区的邀请体系。在写任何代码之前有两个放置问题需要裁决：鉴于[无状态双实例 Relay](../architecture/2026-08-18-stateless-two-instance-remote-relay.zh.md) 决策刻意让每个 Platform Instance 不接触 DSH 业务值，权威的项目与成员存储到底该不该放在运营侧 Platform 上；以及在线状态如何推导才不必另造一套状态模型。生产故事也必须在不越过既有密码学评审门的前提下推进。

## 决策

项目成员是 Platform 能力缝（`@deepseek-ai/dsh-project-membership` Service Definition 与 `@deepseek-ai/dsh-project-membership-core` 文件持久化 Provider）。注册表放在 Platform,因为它与账号、安装、配对授权、Relay 路由记录同属**权威面数据**:这些行的全部职责就是裁决谁可邀请、加入、改标签或移除谁,并按环境命名空间(`development`/`production`)持久提交。每次变更的角色的门都在操作内部执行,经单一写链串行化,以原子重命名整体发布文档,在落盘后发出 roster 失效记录——消费方据此重建缓存视图而非信任旧值。

这一放置所需的边界声明:承载协作**权威**数据并不把 Platform Instance 变成业务值服务,也不侵蚀 Relay 决策。该决策禁止的对象是**消息面**——DSH 会话、提示词、审批、模型、工作区与 Companion 明文必须对转发实例不可见,且那里不做任何排队或重放。成员行对转发形态保持中性:它们不进入 Companion 协议帧,不是逐条消息状态;向成员提问时载荷仍按原样端到端加密。Relay 凭据与路由机制继续独占附着活性;本能力只回答"谁凭角色可达"。

在线状态只从连接活性推导:评估时刻成员至少有一个安装持有活跃平台连接即为在线,最后一个连接关闭即刻离线。没有手动状态、没有闲置推断、没有宽限窗口,也没有投递队列——向离线成员提问立即以稳定错误失败,而不是滞留工作。代价是有意接受的:在线状态回答的是"此刻能否把一个决定交给这个人",只有活性对此诚实。

功能标签始终是项目词汇表拥有的展示与路由元数据:随每个 roster 视图携带,仅 owner/admin 可编辑,永不承载权限语义。角色只治理这一层面,并与 Git 平台权限双向无关。

生产环境继续处于[版本化远端协议](../architecture/2026-08-18-versioned-remote-protocol.zh.md)所记录的独立信道加密评审之后,fail-closed:开发环境通过本地存储上的 keyless 组装场景完成验证,而任何被产出的部署中的提问路由激活都要等该评审通过。本次变更没有任何内容把传输、凭据或明文推过这条线。

## Supersession 检查

两篇被交叉引用的 2026-08-18 笔记均已审计且未被取代。Relay 笔记的保证(实例只转发、不留存变更、不解析业务值)约束的是与本持久化权威存储不同的层面,本笔记正是这种共存关系的边界说明,因此其完整论证保持活跃。远端协议笔记拥有编解码所有权、版本协商以及仍约束生产的密码学评审门;本笔记让位于它而不复述评审门。此前没有活跃笔记拥有项目成员语义。

## Alternatives considered(已考虑的替代方案)

**成员状态保存在某台受信安装的客户端本地。** 否决,因为两个人会把同一仓库克隆到不同机器:单机文件无法仲裁并发重复邀请,丢失笔记本即失去真相,移除传播也无从谈起。多主同步随之出局——邀请接受需要一个唯一仲裁点,而不是收敛。

**复用 Relay 路由或个人配对存储承载项目。** 否决,因为那些行回答"哪个端点接收字节"并保管密封秘密;项目行回答"谁持有什么角色",生命周期语义不同(移除、LAST_OWNER),混用会模糊两种审计。

**用存储的活动时间戳加闲置阈值推导在线。** 否决,因为启发式在线看似可信却在两端说谎:闲置但在线的同事显示离线而实际在工作,合盖笔记本直到计时器触发前一直在线。活性是硬件唯一肯说实话的状态。

**借现有传输立即开通生产路由。** 否决,因为常设评审门按设计就是 fail-closed;先落地不动传输、不碰凭据的注册表能力不会扩大任何信任,这恰恰是它能提前交付的原因。

## 后果

单进程内的重复邀请与交错的晋升/移除都由同一串行写者裁决,有执行器级拒绝测试与跨两代启动的真实 Loader 组装证明。被移除账户立刻丧失枚举能力,其离开使项目级 roster 投影版本递增,包内不变量伴侣守护该流严格单调——包括移除在内。环境命名空间让开发身份即使共享同一存储根也不会与生产冲突。单进程写链的代价是:横向扩展此 Provider 需要换成具备等价比较并交换语义的后端,而不是多开几个此类实例;接口保持 Provider 所有,届时替换也不会把角色门从执行它们的操作中挪走。
