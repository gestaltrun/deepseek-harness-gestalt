# Agent Note: the Sub2API offer card and its one-click installer live in the Desktop Host

Status: implemented

English | [中文](2026-08-28-sub2api-offer-card-installer.zh.md)

## Problem

The Sub2API sidecar (#346, bundle source in the sidecar repository) needed a Desktop-only enablement path. The Web Host is a spawned child, so nothing inside its composition could own downloads, profile writes, or its own lifecycle, and the card had to render a state machine driven by whoever owned that work. Release-backed enablement also had to follow GitHub asset redirects, stream a runtime pack larger than Platform HTTP response limits, and allow the supervised first boot to finish before the Desktop Host startup deadline.

## Decision

The Desktop Host main process owns everything; the card only renders. [`DesktopSub2ApiController`](../../../../apps/desktop/src/sub2api.ts) runs the phase machine `missing → downloading → verifying → installed → starting → running / error`, pushes every transition over a new `sub2api:snapshot-changed` IPC event (the same posture as updater and pairing snapshots), and takes the five lifecycle verbs through the preload bridge. The Host probe polls `GET <web-host>/plugins/dsh-sub2api/quota-snapshot` — a 2xx proves the bundle is mounted and the supervised chain is healthy, because the sidecar registers that route only after a healthy boot; a no-Origin request from the main process passes the sidecar's loopback-peer + loopback-Host admission.

The [installer](../../../../apps/desktop/src/sub2api-install.ts) never shells out to pnpm or the `dsh` CLI: Electron's session-aware streaming `net.fetch` streams both archives into an OS-temp staging directory and serves the loopback health probe, each archive is verified against its own `SHA256SUMS` (plus the runtime pack's inner sums after extraction), the bundle package lands at `$DSH_HOME/profiles/web/node_modules/<name>`, and the profile manifest gains exactly one `dsh.profile.bundles` row — the [profile publication](../../../../docs/user/develop/basic/publish.md) semantics, with every other entry preserved verbatim and the write locked (`withFileLock`) and atomic (`writeFileAtomic`). Platform Account, pairing, and attachment traffic retain the separate redirect-free, HTTPS-only, bounded system-Node helper. The runtime pack strips its top-level directory into `$DSH_HOME/sub2api/runtime`, which is the sidecar supervisor's `binaryDir` default.

Two decisions are worth recording because the ticket text said otherwise:

- **The pack extracts to `sub2api/runtime`, not `sub2api/run`.** The merged supervisor contract makes `<runtimeDir>/runtime` the `binaryDir` default and keeps `run/` for ephemeral state it may wipe on upgrade; extracting binaries into `run/` would break replace-on-upgrade and mix with `admin-password` and logs.
- **Disable writes a profile patch row, not a config override.** Patch rows replace a row's whole config, so an `enabled: false` override would have to restate the sidecar's full config. The installer writes the exact row `{ id: 'dsh-sub2api-sidecar', disabled: true }` into the profile's own `cordis.patch.yml` — entry-level disable, user-layer precedence, nothing else touched — and refuses to coexist with a user-owned row for the same id.

Rollback: any installer failure after the manifest patch restores the previous manifest text and removes this run's extraction, so the Web Host never boots a half-installed component. If the first restart after a fresh install fails, the controller removes the row and extracted files, restarts again, and reports the failure with the rollback prefix.

Downloads resolve from `DSH_DESKTOP_SUB2API_SOURCES` (a JSON file path, otherwise `sub2api-sources.json` beside the packaged main entry) holding the four artifact URLs. No file means the deployment has no approved component feed: the card renders the offer, and enabling reports the missing configuration. A present-but-invalid file degrades to the unavailable controller carrying the reason rather than crashing Desktop boot.

The controller publishes `starting` before the controlled restart ([`replaceWebHost`](../../../../apps/desktop/src/main.ts), also used by the crash-respawn path) stops the child. The restart spawns a fresh child through the existing [`spawn-web-host`](../../../../apps/desktop/src/spawn-web-host.ts) seam, reloads the window and the native overlay onto the new port-0 URL, and re-points Companion RPC; sessions survive on disk. The overlay therefore sends Models requests only to the current Host. Its Settings document publishes section selections under the live request id; the main process accepts only same-request Settings updates, retains the selected section across Host replacement, and attaches the view before making it visible so the native window presents the selected content immediately. Running state renders the current Host's same-origin native Sub2API account workspace by default, with status and lifecycle actions in the Settings header; the workspace follows the Desktop theme and locale and never navigates the Session Surface. Desktop embed mode composes the native account table, proxy manager, and Composite-route dialog in that workspace, fixes the account table to the product-approved columns, removes its search and filter row, Auto Refresh, More Actions, and bulk-update entry, and right-aligns Refresh, Composite Routes, and Create Account. Its account create/edit forms hide pool mode, billing-rate synchronization, automatic upstream-rate probing, and quota controls while preserving Sub2API's existing defaults and save payload. The borderless frame and neutral light/dark surfaces fill at least the Settings viewport; the embedded account table preserves horizontal table scrolling but expands vertically, so the Settings content column owns the only page-level vertical scrollbar and no contrasting footer band appears below the table. The sidecar derives the provider model catalog by intersecting the group-bound inference key's live `/v1/models` with the complete model-id lists saved by each account's latest successful upstream synchronization in that Composite group. Capability metadata can enrich those models but cannot add or remove them. The sidecar refreshes after successful management mutations and polls as a cache-invalidation fallback. A failed refresh retains the last provider settings; an empty intersection removes the provider, so neither configured platform defaults nor operator configuration can invent subscription capabilities for the account pool. Every controller-owned component replacement and an ordinary Desktop boot with an installed, enabled component supply a 180-second startup deadline; ordinary boot without an enabled component and crash recovery retain the 30-second deadline. The desktop bundle grows by `tar`, `js-yaml`, and `@deepseek-ai/dsh-home-paths` — the install stays inside the app, and the installer size never carries the runtime pack.

## Alternatives considered

**Put the installer in the Web Host composition.** A bundle plugin could download and self-mount only by editing its own profile out from under a running Loader and restarting itself — the Host would still own the restart, and downloads would die with the child they control. Rejected: the Desktop main process already owns child lifecycle and outlives Web Host restarts.

**A Web Host RPC for start/stop.** The sidecar bundle would need a new control service, and the Renderer would reach privileged install verbs through the page's transport. Rejected for A2: it adds a bundle-side API the card cannot assume on older bundles; the profile patch row uses the documented override lever with zero bundle changes.

**Store the state machine in the renderer.** The card must survive window reloads across the restart it triggers, and two surfaces (main window + overlay document) render it. Rejected: the Host-pushed snapshot is the same discipline the updater and pairing snapshots already follow.

## Consequences

Browser `dsh web` has no entry point (ui-desktop is Desktop-overlay-only), and the card renders nothing without `window.dshDesktop`. The release-backed Electron gate force-builds the exact Gestalt source, removes inherited credential-bearing environment entries, copies only its approved credential file into a private initialized profile, and installs one public checksummed sidecar Release. Its CDP bridge gives bounded public checksum and tag lookups 120 seconds instead of the driver's 10-second default. It drives account and Composite-route creation through the native embedded forms, requires the live gateway and provider settings to expose complete account-backed model capabilities, and sends a real model request through the selected route. Evidence records the exact Gestalt and sidecar identities and fails unless artifacts are secret-free, product processes stop naturally, the private runtime root is removed, and its CDP port closes.

The `web` profile is pinned by name: the Desktop Web Host is `dsh web`, alias of `--profile web`, so the installer edits that one profile. A Web Host boot that fails with the bundle mounted still shows the Host error page with no card; recovery is re-running uninstall from a working boot or removing the bundles row by hand. The installer rollback covers failures it owns, and a fail-loud boot error names the plugin. The source manifest may combine a newer sidecar bundle Release with an older unchanged runtime-pack Release; each asset remains paired with its own checksum document, and the E2E resolves the bundle tag to the exact sidecar commit.
