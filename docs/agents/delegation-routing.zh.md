# 委派路由与上下文复用

[English](delegation-routing.md) | 中文

在派发或继续子 agent 前使用本参考。它治理任务到模型的选择与子会话上下文复用，但不要求任何特定 provider。

## 判断是否委派

文件发现、状态、精确转换和小型本地检查使用确定性工具直接完成。边界清楚的独立任务在需要隔离上下文、并行、不同模型或独立审查时再委派。一个可变工作树保持单一 writer；只读调查和审查可以并行。

选择路由前，先明确产物、读写范围、风险、验收证据、必要背景和独立性。源码与可观察检查决定验收，模型信心不决定。

## 显式选择模型

根据任务、当前用户限制、已验证输入能力和同类仓库工作的实测表现，选择可用 provider 与模型。运行时支持时同时传入两个路由字段，不通过省略来继承父级路由。区分三类证据：

1. **配置能力**说明当前 adapter 暴露什么。
2. **官方来源声明**支持产品档位或输入能力，不支持通用排名。
3. **任务证据**记录该路由能否在本仓库产出准确、可核验的结果。

仅在对应档位或经过实测的等价模型可用时采用以下默认分工：

| 任务 | 默认档位 |
| --- | --- |
| 确定性查找或转换 | 直接工具 |
| 简单批量抽取或分类 | Luna 类高吞吐模型 |
| 边界清楚的常规编辑与测试补充 | Terra 类或 GLM Flash 类模型 |
| 通用后端与终端实现 | GLM 类工程模型 |
| 长程自主实现 | Grok 类或 Kimi 类长程模型 |
| 跨大量来源的广域证据综合 | Kimi 类长上下文模型 |
| 前端实现或视觉验证 | Gemini 类或视觉 GLM Flash 类模型 |
| 架构、跨包生命周期或安全、困难根因、独立高风险审查 | Sol 类或经实测的等价模型 |

模型名字不能证明输入支持。截图只发送给已验证可接收图片的模型与 adapter；纯文本模型只处理文本任务。媒体生成模型不是文本编码 agent。遵守被排除的模型与 provider，不做静默 fallback。官网标价描述厂商档位，不是中转账户账单。不得虚构不存在的 effort 参数、cache 保证或 benchmark 排名。

具体安装可以补充映射。[可选 CLIProxyAPI profile](delegation-routing-cliproxyapi.zh.md) 记录其中一套映射，其他安装无需支持它。

## 复用或新建

运行时提供目录时，在新建子会话前检查相关直属可继续子会话。

**继续直属子会话**适用于相关后续：其证据仍有效、固定模型仍匹配、范围与权限仍匹配，且不要求独立判断。发送差量 brief：新目标、当前基线、变化文件或失效事实、保留约束和完成证据。后续消息只安排子会话下一回合；它不会改变路由或重定向正在运行的工作。

**新建子会话**适用于独立审查、模型变化、陈旧或系统性错误假设、无关工作，或精简交接成本低于修复旧上下文的任务。

**fork 父会话**只用于任务确实依赖父会话多个已完成回合中的决定，且精简 brief 会丢失必要背景的情况。fork 不是独立审查，也不表示 provider 侧 cache 复用。

子会话目录不是全部 workspace 历史。只有直属可继续子会话是后续消息目标；不得跨 parent 接管子会话，也不得检查私人 session 存储来制造连续性。持久决策应写入 specification、Context 文档和 Agent Notes 等仓库 owner。

## 派发 brief 与验收

使用最小任务包：

- 产物与可观察完成证据；
- 必要 issue、specification、文件与当前 commit 或工作树差量；
- 读写范围与明确排除项；
- confirmed、hypothesis、unknown 的区分要求；
- 预期 findings、实际检查与未解决限制。

只有保留证据的价值高于陈旧上下文、纠错、排队等待与偏见成本时，复用才节省重建。不要使用任意 token 阈值或声称持久 KV cache。若某路由反复违反证据或工具要求，缩小范围并明确纠正一次，然后在更匹配的路由上新建会话。
