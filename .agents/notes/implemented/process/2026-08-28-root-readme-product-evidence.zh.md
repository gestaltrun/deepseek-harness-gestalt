# Agent Note: 根 README 描绘獭子哥产品层

Status: implemented

[English](2026-08-28-root-readme-product-evidence.md) | 中文

## 问题

根 README 把獭子哥描述为桌面端与手机端工作空间，但没有准确说明它和 DeepSeek Harness 官方仓库的关系。读者无法看出哪些能力来自 DSH 基础、獭子哥增加了哪些产品功能、集成了哪些社区插件，以及哪些工作正在交付或仍处于计划阶段。

简短的演示集也遮蔽了已完成产品工作的广度。完整包清单则会产生相反问题：它会重复生成目录，并用实现结构代替产品说明。

## 决策

根 README 将獭子哥定义为官方 DSH 之上的产品层。产品方向包含四部分：补齐可安装产品、保持 DSH 组合方式与入口兼容、集成经过审阅的社区插件，以及让多个客户端共享一份持久权威。README 把上游兼容视为持续的仓库工作，不会声称开发者预览阶段的每个 commit 都可相互替换。

英文产品名是 **Gestalt**，中文产品名与 IP 角色是 **獭子哥**。产品首页保存并展示已经确认的角色设定图。现有包名、应用标识符、发行 tag 和历史引用保持不变，直到另一项协调重命名明确要求迁移。

由 tracker 支撑的产品地图把獭子哥增量划分为多个产品域。`DONE` 要求能力已经合并进 `master`，但不表示它已包含在最新打包版本中。`DOING` 要求存在正在交付的 PR（Pull Request）。`TODO` 要求存在已经选入产品路线图的开放 Issue。每个非空状态都会链接支撑它的 PR、Issue、权威参考或插件目录。该地图介绍 DSH 基础周围增加的产品功能，不重复官方 DSH 的包目录和工具目录。它是 README 中唯一的产品状态清单；功能导览只解释已经完成的行为，不重复交付状态。

功能导览使用经过验收的产品录屏展开地图，覆盖 Workbench 与 Better Sidebar、Side Chat、Schedule、AI Browser、Workspace Reference、Annotation 和 Mobile Companion。每个嵌入的 GIF 都来自已合并改动所验收的真实产品路径，并在 URL 中使用不可变的仓库对象 id。详细来源保留在所链接的 PR 中。

安装步骤保持简短。README 将首次运行流程链接到用户指南，将组合方式和生命周期语义链接到架构与应用参考，将外部集成链接到插件目录，并将贡献者流程链接到开发文档。

## 曾考虑的替代方案

**只把獭子哥描述成另一个 DSH 客户端。** 不予采纳：Desktop、Mobile、Workbench、发行、验收和社区集成共同构成产品层，不是一项客户端实现。

**列出每个包和工具。** 不予采纳：生成目录和源码负责完整清单。产品地图按用户可见的结果组织獭子哥增量。

**只展示已完成工作。** 不予采纳：活跃产品方向仍会不可见。由 tracker 支撑的 `DOING` 和 `TODO` 可以区分已经承诺的交付与计划，又不会把开放工作写成已发布能力。

**使用 mock 截图或概念图。** 不予采纳：它们无法证明当前产品行为。已验收的产品录屏可以提供具体证据，又不会把 README 变成测试报告。

**嵌入每一段可用录屏。** 不予采纳：大量重复动画会拖慢页面，并遮蔽主要产品域。每个功能导览使用一段代表录屏或一组对比即可。

## 后果

读者可以一次看清官方 DSH 基础、额外的獭子哥产品层、当前交付和计划工作，再按产品域检查真实工作流。状态地图可能产生漂移，因此每次涉及产品范围的 README 改动都要根据实时 tracker 校验 Issue 与 PR 链接。README 不再用第二个路线图章节重复这些状态。详细运行时行为、配置、兼容限制和验证仍由各自的权威文档与 PR 维护。
