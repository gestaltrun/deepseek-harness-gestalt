## Implementation organization

This is one cohesive agent-instruction policy change with shared root/skill/reference owners; use one ticket and one isolated writer to avoid concurrent edits to the same instruction files. The coordinator owns durable planning, dispatch, review, acceptance, and the retro decision gate; it does not implement or merge branches. The writer owns implementation and fixes on its ticket branch. A merger subagent alone integrates the ticket branch and any accepted retro changes into the specification branch, which retains one pull request to master. The four prior local audit/research documents are background evidence only, not implementation state or authorization to copy unrelated files.
