# Local modifications

Every divergence from the pinned upstream commit in [UPSTREAM.md](UPSTREAM.md). Product behavior belongs in `@deepseek-ai/dsh-client-ui-workbench`, not here.

1. **Workspace package manifest** — `package.json` / `tsconfig.json` / `tsconfig.dts.json` / this file / `UPSTREAM.md` are repository-owned. Upstream `package.json` name `dsh-better-sidebar` is `@deepseek-ai/dsh-client-ui-better-sidebar`; the upstream plugin id, Cordis name, and settings namespace stay `dsh-better-sidebar`, and the workspace version follows the monorepo root. The manifest maps upstream runtime dependencies to workspace peers and development dependencies, while `react-icons` remains a bundled dependency. `tsconfig.json` project references use this repository's package paths (`../../core/session`, not `../../session/session`). The snapshot is not a `tsconfig.client.json` project: those references would pull host `Context` merges into the client program.
2. **`src/config.ts`** — `import z from 'schemastery'` is `import z from '@deepseek-ai/schemastery'`.
3. **`src/context-types.ts`** — the upstream `CordisContext & SidebarContextShape` intersection keeps the sole `betterSidebar` Cordis augmentation. This repository adds the concrete client connection and Session-admission types plus the provisional Session and `uiRenderer` faces required by the canonical Side Chat composition.
4. **`src/invariant.ts`** — companion rewritten to the repository invariant gate (`PACKAGE_NAME` matches this workspace package).
5. **`tsdown.config.ts` / `src/client/chunk-loader.ts`** — client factory id is the workspace package name; Host/Client build faces split the Node library from the browser chunks; the plugin-registry `client-registry.js` channel is omitted; chunk and client externals request `@deepseek-ai/cordis`. The Node library build emits only snapshot sources to `lib/types` through `tsconfig.dts.json` (`noCheck` and `noResolve`) so published declarations exist without joining the client aggregate or emitting dependency declarations beside dependency sources.
6. **`src/bundle-route.ts`** — `LIB_DIR` is the package `lib/` directory, not `dirname(import.meta.url)`. Source launch (`tsx`) otherwise looks for `src/client-terminal.js` and the terminal / editor / mermaid chunks 404.
7. **`src/client/BrowserView.tsx`** — when `ctx.get('workbenchBrowser')` is published, the tab renders that official chrome. The sandboxed iframe remains the fallback for a standalone snapshot install.
8. **`src/client/service.ts`** — `setPanelOpen(open)` expands or collapses the right workbench panel. The official preview and first Agent tab use it; a type-only `openTab` does not expand. `createTab` receives the `openTab` seed so a descriptor can reuse an explicit id, title, or meta instead of minting a fresh identity.
9. **`src/client/TabBar.tsx` / `src/client/sidebar.module.css`** — under `window.dshDesktop.chromeOverlayShow`, the `+` menu opens in the Desktop native overlay view instead of the in-page `Menu`. The Desktop top Workbench aligns to the 36px Window Chrome and uses only the flexible unused space after `+` for window dragging; tab dragging temporarily returns that space to the drop target. The bottom Workbench and browser-only `dsh web` render no window drag space, and Web keeps the in-page menu, upstream tab context menu, and 34px tab strip.
10. **`src/client/Sidebar.tsx` / `src/client/state.ts` / `src/client/sidebar.module.css`** — panel resize keeps the conversation scrollbar gutter and scrolling intact and makes its thumb transparent until release so Chromium does not flash an overlay scrollbar while the scrollport changes size. Fresh Session panes start on the enabled tab-type cards instead of an automatic Files home; layout sanitization removes only the exact legacy automatic record and retains user-created editor and file tabs.
11. **`src/client/index.tsx`** — the Desktop overlay document (`data-dsh-desktop-overlay` / `?dsh-desktop-overlay=1`) does not mount the snapshot `Sidebar` into `document.body`. Overlay Settings still use the Host chrome settings seat.
12. **`src/sidechat-routes.ts` / `src/index.ts`** — live Side Chat Agent handles and pending snapshots belong to one plugin activation. Teardown closes route admission, waits for admitted calls, clears pending snapshots, and releases every handle before the plugin becomes quiescent.
13. **`src/client/SideChatView.tsx` / `src/client/index.tsx` / `src/client/api.ts` / `src/client/subagent-detect.ts` / `src/context-types.ts` / `src/sidechat-core.ts` / `src/sidechat-routes.ts`** — the Side Chat tab keeps only child creation and lifecycle. It stages a provisional renderer identity, mounts the repository `conversation` slot through `uiRenderer.mountSession()`, and creates the Host Agent and Session under the same id only when the first message is submitted. The provisional row stays out of subagent catalogs and counts. That first admission captures parent history, installs the provisional model and permission choices, and publishes the child. A runtime admission adapter routes prompt/cancel, queue/steer, permission, skill-catalog, and model operations while hiding the inherited seed prefix. The snapshot's thread switch, promotion toolbar, transcript polling, message renderer, composer, header-info route, connection mirror, related CSS, and unused locale strings are absent. The compact header omits Session navigation and the preset label while the current child catalog, jobs, and schedules resolve against the child id. Descendant selection retargets the explicit renderer without changing shell selection, and the tab retains its root Side Chat id for lifecycle cleanup; workbench terminals retain their own scope.
14. **`src/git.ts`** — an explicit child-repository selection that is absent from the current discovery result fails instead of falling back to the first repository and applying a mutation to the wrong checkout.
15. **`src/agent-opens.ts`** — `sidebar_open` delivery isolates failed WebSocket senders, detaches them, and retains each request until at least one connected view accepts it.
16. **`src/loopback-allowlist.ts` / `src/index.ts` / `src/client/browser.ts` / `src/client/BrowserView.tsx` / `src/prefs-shared.ts`** — Host and Client share one loopback allowlist parser. Security prose distinguishes the opaque default sandbox from the own-origin privileges granted only to explicitly allowlisted loopback pages.
17. **`src/client/locales-zh-HK.ts` / `src/client/locales-zh-MO.ts` / `src/client/locales-zh-TW.ts` / `src/client/locales.ts`** — regional Traditional Chinese dictionaries use descriptive export names so the repository's zh/en fallback parity gate does not mistake them for incomplete fallback pairs. The Macao and Taiwan module descriptions name their actual locale.
18. **`src/client/intercept.tsx`** — disabling chat file-open interception also leaves the produced-files turn tail with the official `ui-deliverables` owner; sidebar chips never bypass the setting.
19. **`src/client/state.ts` / `src/client/sidechat-restore.ts` / `src/client/service.ts` / `src/client/subagent-detect.ts` / `src/client/builtins/tabs.tsx` / `src/client/api.ts` / `src/sidechat-core.ts` / `src/client/SideChatView.tsx` / `src/sidechat-routes.ts`** — Side Chat tabs restore from durable Session data after the origin-scoped strip is lost. Apply-lifetime projection subscriptions restore published, unarchived direct children without replacing the active tab. The Host serializes close with first publication and reports durable identity; close waits for release and archive before removing the tab, and client teardown prevents late commits. A local tombstone covers projection delay. `?dsh-sidebar-reset` skips restoration, and shared core helpers own root-thread identity.
20. **`src/client/intercept.tsx` / `src/client/sidebar.module.css`** — the produced-files "show in folder" action carries a dedicated `producedFolder` class that resets the native button border and background; sharing the `+N` counter's `producedMore` class left the browser's default button chrome visible.
21. **`src/path-security.ts` / `src/index.ts` / `src/html-route.ts`** — read routes (`fs.read`, `/sidebar/file`, `/sidebar/html`) resolve existing files through `resolveReadablePath` without workspace containment, so an explicitly opened editor tab, its markdown images, and its HTML preview work for files outside the session workspace. Write routes (`fs.write`, upload), `fs.tree`, and `fs.search` keep the containment guard.

22. **`src/client/sidebar.module.css`** — right and bottom workbench panels use `contain: style` only. `contain: layout` shifted an absolutely positioned Desktop panel so the tab strip sat off-screen and the official page covered the sidebar tab list.
23. **`src/client/service.ts`** — an `openTab` seed with a path or URL whose active pane is in the bottom tree lands in the right workbench before minting. Type-only `+` clicks still follow the pane that owns the menu.
24. **`src/client/state.ts`** — closing the last docked tab in the right workbench collapses that panel; closing the last docked tab in the bottom workbench collapses the bottom panel. Remaining floats do not keep an empty docked tree open after `closeTab`; undocking the last docked tab does not collapse the panel.
