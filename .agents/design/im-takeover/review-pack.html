1模块：六个深模块，平台只是 adapter

每个模块对外接口小、对内隐藏多；adapter 只在真实平台与模拟之间变化。

为什么不复制 HiQ / Travel-Team 整包
HiQ 的 DWS alias 与本机不同、产物为不可拆改的 bundle；Travel-Team 的轮询与出站证据机制可靠但耦合电商业务与自有存储。两个项目都只吸纳机制，模块按 DSH 接缝重新组织。

2数据流：真实与模拟共享被测路径

被测 Agent 不知道自己在被模拟；隔离由实例上下文强制，不靠提示词。

  • 事实 旺旺参考实现已有游标追赶与出站证据；HiQ 已有 outbox 与恢复机制——只吸纳机制。
  • 采用 三分进度：已接收 / 已提交 Agent / 对外已发送，重启后按进度补交且仅一次。
  • 待核验 DWS 真实收发与回执仅有 dry-run/mock 级证据；旺旺无 whoami，商家身份绑定路径未知。

3插队与触发：新消息立刻到场，但不动运行中的工具

新触发直接插队 用户已确认

不等当前轮 FIFO 排队。候选机制是现有 steer / 优先 inbox，在最近安全的 step boundary 以高优先级生效；不强制中断模型生成、不动已开始的工具。

群触发三选多 多选已确认

被 @ ／每 N 条新消息／定时（仅有新消息）。本轮采用 任一满足即触发、同批只提交一次、N 计未提交消息、固定周期、提交成功才推进。

已确认（用户两次明确）：插队在最近安全的 step boundary 以高优先级生效，不强制中断模型生成、不动已开始的工具执行。方案即按此设计，不再是开放问题。

4隔离、生命周期与安全：四条硬规则

重启零定制

完全跟随普通 Session 默认：该续跑就续跑、该停就停。显式停止的模拟实例不可复活。

配置变更只影响新建

清除/改换模拟目标配置不影响运行中实例；旧实例固定创建时目标，继续收发并可停止。

权限与身份

外部 IM 发言不是 owner 指令；审批只在 DSH 页面；凭据只以 reference 出现在配置与日志。来源不可证明时保留“不确定”，不按昵称猜。

模拟边界

未配置模拟目标的 workspace 没有模拟工具；被测 workspace 不因成为目标获得工具；模拟只替换 IM 投递，其他工具的副作用各自负责。

5并行基线：固定同步快照开工，单一集成者合入更新
