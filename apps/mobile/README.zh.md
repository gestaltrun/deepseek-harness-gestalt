# DeepSeek Gestalt Mobile

[English](README.md) | 中文

这是当前 Installation 的 Mobile Account 与 Personal Pairing shell。GitHub 授权前，它通过 `@capacitor/device` 读取原生设备名称及 iOS 或 Android 平台，将该展示绑定到生成的 Account Session，展示双语数据保留说明，在应用外打开授权，并以 P-256 证明轮询 Platform。登录后，Mobile 会在本地解码粘贴或浏览器相机 QR 扫描得到的同一份完整端点邀请，创建 XKpsk3 消息 1 与消息 3，显示由已完成握手哈希派生的认证词，并轮询不透明 mailbox 等待 Desktop 确认。Desktop 为每个 Personal Pairing 创建一个 Mobile Relay credential 与随机 32 字节 attachment key；Platform 只登记 credential digest 并复制已鉴别 Installation 展示。Mobile 会把每组 Snow 密封 grant 与 attachment key 打开到一个带版本、账号隔离的受保护文档中；该文档会拒绝重复 pairing id，并保留多组独立 pairing 与一个显式选择。加载原生 version-1 或无 version 的 IndexedDB 文档时，Mobile 会把其中唯一一条 record 迁移到 version 2，从该 record 的 pairing id 推导缺失的 Mobile grant selector 与显式 selection，并在暴露 authority 前持久保存替换文档；多条 legacy record 或冲突 selector 会在不改写原文档的情况下失败。Desktop 名称只会在已鉴权前台同步后进入该文档。选择 Desktop 会排空上一条 Relay，使其 channel 与 projection 失效，持久保存并展示新选择及其最后确认的缓存，然后异步启动所选 grant 的重试 attachment；完成鉴权与同步前，mutation 会保持 disabled。解除配对只撤销并擦除所选 pairing，退出登录与 Account 切换则保留彼此隔离的 pairing 文档。

入口只接受一套实际运行的生产身份，由 `VITE_PLATFORM_ORIGIN`、`VITE_PLATFORM_CALLBACK_URL`、`VITE_PLATFORM_GITHUB_CLIENT_ID`、`VITE_PLATFORM_CREDENTIAL_REFERENCE`、`VITE_PLATFORM_DATABASE_IDENTITY` 与 `VITE_PLATFORM_IDENTITY_NAMESPACE` 提供。字段缺失、localhost、非 HTTPS origin 或回调不匹配会在本地存储、渲染或网络流量前失败。

共用 Mobile 入口内置 `@capacitor/browser` 与 `@capacitor/device` adapter。授权尝试准备完成后，继续按钮的用户激活会直接调用 browser adapter；入口没有 `window.open`、弹窗、当前上下文导航或携带 token 的自定义 URL 回退。Personal Pairing 页面让取消与仍在等待的 `getUserMedia` 竞速，并以 `@zxing/browser` 读取一个 QR 值；成功、失败、取消或卸载后会停止 decoder，并停止当前或稍后返回的每条相机 track。不支持的相机 API、权限拒绝、无相机、空结果、畸形链接、过期、重放与跨账号尝试都会显式失败；QR 与粘贴绝不会创建不同的邀请或握手路径。`IndexedDbInstallationAccountStore` 将所选数据库 identity 写入数据库名；原生打包负责提供稳定 WebView origin。缺少 `crypto.randomUUID` 会在渲染前失败，因为创建 Installation id 需要安全浏览上下文。

## 共享 Session 呈现

加密 channel 只传输一份 JSON Mobile projection：conversation 使用数组，turn index 使用 entry 数组，pending interaction 只包含 id、Session id、kind 与 domain payload。发布前，authenticated receiver 会校验每个必需 conversation 字段以及已知 node、Tool presentation、content 或 pending-payload discriminant；未来 node kind 会转换成共享 unknown-node carrier，未知 Tool card 会保留为可扩展 render intent，畸形的已知 content 则会被拒绝。随后，本地 adapter 构造 Client Runtime 的 `SessionListState`、`WorkspaceView`、`ConversationSnapshot` 与 `PendingWait` presentation carrier。pending responder 调用同一 generation 绑定的 channel，并把 accepted 或 rejected receipt 返回共享 Approval 或 Ask User owner；Map、class 与 callback 都不会跨越 wire。

打包后的 Mobile 入口把列表／详情导航留在 `apps/mobile`，但既没有 Mobile Session 摘要模型，也没有 Mobile conversation-node router。Session 分组与支持键盘聚焦的行执行公共 `ui-workspace` presentation，终态 conversation node 则执行公共 `ui-conversation` keyed presentation。已确认的新建空白 Session 会跨分页与重复的已鉴权 refresh 保持选中，直到 detail view 已提交，或 Desktop 报告它不再空白；只有同一物理 connection generation 可以拥有或确认该选择。全屏 detail root 会绑定共享 content width、composer gutter、card width 与长草稿上限，而不挂载 Desktop `ConversationRoot`。订阅式 clock 更新共享相对时间标签。tail history response 会替换权威 conversation；`loadOlder` 会发送最旧可见 sequence，并 prepend 通过连续性校验的 page。locale 与 light/dark theme 会进入共享 conversation、Tool、attachment、question 与 Workspace 实现。图片通过 `ImageGallery` 渲染；普通 Tool 名称使用 Desktop 内置 keyed roster，只有未知名称使用 `GenericToolCard`。Mobile 绝不挂载 Desktop columns、Settings、model selection、plugin configuration 或 terminal input。

打包入口 snapshot 会构建并加载 `main.tsx`，把它的 `launchMobileProduct` dependency 解析到经过鉴权、绑定 generation 的 fixture；生产 resolver 只会调用实际运行的 start callback。keyless fixture 会发送 `session-created` result 与已鉴权 refresh，以执行共享 Workspace 和 Ungrouped 的空白 Session 可见性。构建入口 snapshot 还会以 390 px 的英文／dark 与中文／light 环境执行共享 Markdown、code、image、已知与未知 Tool、diff、Host error、未来 node fallback、Approval、Ask User 与长 composer content，并覆盖有界滚动与可触达 action。它不会给 `main.tsx` 增加 keyless 产品选择，不运行 model round，既不证明真实 Desktop transport，也不证明原生 WebView 执行。`apps/mobile/prototype-companion` 与开发端口 5173/5174 都不是 Mobile 产品验收 origin。

实际运行入口会按 Paired Desktop 使用 Personal Pairing 所有的 HKDF 派生 AES-GCM 密钥，密封一份带版本的已鉴权 Workspace、Session 与 transcript projection 快照。该快照使用 `companionCacheDatabaseName` IndexedDB namespace（`${accountStorageNamespace(environment, accountId)}:companion-cache`），所以账号切换会把缓存和回执与受保护的配对权限隔离开。Mobile 只把它恢复为 Remote Offline 只读展示，在前台同步完成前禁用所有 mutation，并提供按 Desktop 清除缓存。附件字节、终端内容、spill 文件与凭据永不进入缓存。`CompanionUncertainOperationSettlement` 会在传输前预留不可淘汰的 `prepared` Operation Receipt，并在第一次 Relay 发送尝试之前持久改为 `unknown`。该 fence 之后的失败会保持未知，直到 single-flight `query-operation-status` 对账返回权威结果或显式 absent；Mobile 永不重放 operation。
附件控制器会读取用户选择的浏览器 `File` 字节，用 attachment key 加密后清除本地副本，只把密文连同当前配对范围的授权上传到运营中的 HTTPS `remote-attachments` 路由，校验返回的一次性 capability，并只把有界 `offer-attachment` operation 交给 Encrypted Companion 发送方。由 runtime 所有的 permit 会把整个异步传输绑定到一个物理连接 generation；每个外部 await 以及 upload 和 send 都要求该 generation 仍处于已同步前台状态。mutation channel 会把 operation id 与 send completion 返回给 Mobile surface；surface 会关联 Desktop 确认、attachment 拒绝、Host 失败与重连 status，而不会把它们当作搜索结果。attachment 拒绝或 Host 失败会成为可见 alert。surface 只拥有一个尚未结算的 attachment operation：该 operation 处于 sending 或 uncertain 时，再次选择文件会在调用 channel 前失败；确认、拒绝、失败或对账 status 会释放该 operation id。如果 sender reject，或在该 generation 已失效后 resolve，`CompanionAttachmentDeliveryUncertainError` 会保留 operation id，surface 会显示 uncertain 状态，直到 `query-operation-status` 完成对账。Mobile 搜索把裁剪后的查询发给 Desktop，并且即使 Companion Cache 中没有对应 Session，也会展示每个关联的权威 Session id/snippet 对；缓存中的标题、Workspace 标签、摘要、transcript 与子串匹配绝不会标注或创建搜索命中。`operation-failed` 会保留 Host HTTP 状态、wire 校验失败、业务 code/message 或超时，并作为 Mobile 可见错误展示。

当 Mobile 在已鉴权的 Companion major 4 attachment 上保持前台时，打开 Session 会发送 `observe-session`，返回列表则清除该选择。revision 更高的 `session-live` 替换会更新已打开的共享 conversation，以及隐藏 Session 的摘要、过滤归档项后的位置与 Workspace 归属，无需手动刷新。同一物理 Snow channel 上 revision 更高的 `foreground-sync` 会从 offset 0 开始 baseline，但不会替换 surface receiver、清除 operation correlation，也不会丢失已观察焦点与保留的 conversation。在该分页 baseline 完成前到达的实时替换会进入有界合并队列；超限或连接丢失会拒绝当前 generation，随后由正常的前台重连取得新的权威 baseline。经过尺寸裁剪的 live conversation 会设置 `hasMore`，因此“加载更早内容”会把最早保留的 sequence 发送到关联 history 链路。隐藏 Session 永不接收 conversation 字节。

pnpm --filter @deepseek-ai/dsh-mobile build

## 已知限制与暂缓事项

- 实际运行入口选择 `SnowMobileHandshakeClient`、`SnowMobileAttachmentOwner` 与 foreground Relay lifecycle，不提供 keyless 或开发产品选择。入口要求 `VITE_REMOTE_RELAY_WSS_URL`、`VITE_REMOTE_RELAY_ATTACH_TIMEOUT_MS`、`VITE_REMOTE_RELAY_HEARTBEAT_INTERVAL_MS`、`VITE_REMOTE_RELAY_RECONNECT_DELAY_MS`、`VITE_REMOTE_RELAY_INBOUND_MAX_BYTES` 和 `VITE_REMOTE_RELAY_INBOUND_MAX_MESSAGES`，且都会在渲染前校验。每份 Relay ready 或 peer-update projection 都必须在读取密钥或开始 IK 前指定当前所选 grant 的 pairing selector；不匹配会丢弃产品连接与 mutation authority，同时保留所选 Desktop 的只读缓存。匹配的 credential-bound metadata 会开始一次新的 IK 尝试。Mobile 会从 IK2 打开 Desktop 的加密 Companion offer，把自己的加密 offer 作为下一条 Relay ciphertext 发出，此后才构造协商后的 codec；版本交叉会在同步或应用数据前失败，并指出必须更新的 endpoint。
- 加密 projection cache、清除缓存 UI 与 Operation Receipt owner 已接入。Session 创建、prompt、cancel、interaction 与 attachment mutation 使用同一条结算链路；恢复出的权威成功、Host 失败与显式 absent 会更新关联的 Mobile surface，并触发所需的有界刷新。
- attachment-bound Snow channel 拥有解码 projection 与 result，并且是 Companion operation 的唯一 sender。它会把一个物理 generation 的 mutation、content 与 observation adapter 原子绑定到 `MobileCompanionSurface`；旧 attachment 的 receiver、pending responder、prompt confirmation、observation 或 channel 不能经 replacement dispatch。Companion major 4 会把权威 Session 与 Workspace 发现、Workspace 或 Ungrouped Session 创建、带真实 Host running 状态的 conversation history 与实时 projection、等待 confirmation 的 prompt 提交、取消、Approval 与 Ask User settlement，以及摘要校验后的历史图片字节送入共享 Web 展示。关联失败会 reject 待处理工作并保持可见；确认后的 mutation 会触发一次有界 history 与列表刷新。
- `CompanionForegroundRuntime` 是 Relay start/stop 的唯一所有者。选择发生变化时，它会让 mutation 权限失效，释放上一组 pairing 的 projection 与 Relay，绑定新选择的只读缓存，并且只允许其已持久化 grant 重试 attachment；它绝不合并不同 Desktop 的 Session 状态，也不会自动回退。配对与可见性共用一条转移队列，进入后台会停止 WSS；成功解除所选 Desktop 配对会丢掉该 grant，使之后的可见性变化不能再启动其 socket，同时保留其他每组 pairing。解除配对会运行每项自有清理；任一拒绝都会保留可见、未解决且可重试的失败状态，不会返回 ready 配对页面。每个物理 attachment 的 ready/lost 转移都会创建或失效一个同步 generation，transport error 也会清除 `socketOpen` 与 `synchronized`。在完成已鉴权同步前，Mobile 入口不会虚构 Desktop 名称、写死离线状态、Device Principal 或本地 Session。附件工作使用当前 generation 的 mutation permit，只上传密文，并通过加密 channel 发送返回的 capability；搜索结果与 Host 失败只来自关联的 Desktop result。此前已鉴权内容可在重连期间保持可见，但 Session mutation、搜索与附件控件会在当前 generation 重新同步前保持 disabled。Mobile 不提供后台通知投递；只有打开应用或回到前台后，它才会获知 Desktop 当前状态。
- 发布验收会在 Node 22 与 24、iOS Simulator WKWebView 和 Android Emulator WebView 中运行仓库内确切的 Snow JS/WASM 包。原生 WebView runner 会覆盖配对、重连、新临时密钥、双向传输、篡改、重放、乱序、跨配对与最大帧限制；本地 Vite 与 `prototype-companion` 不是该产品链路的证据。
- `apps/mobile/ios` 与 `apps/mobile/android` 是 `com.alibaba.gestalt.mobile` 的仓库内 Capacitor 发布工程。自定义受保护存储插件、原生文件 input picker、相机权限、`@capacitor/app` lifecycle、App Store export 与 release-key APK 流程都属于该 shell。完整的一次性配对邀请只会通过应用内 QR 扫描或粘贴进入；原生工程不登记可被拦截的自定义 URL scheme。
