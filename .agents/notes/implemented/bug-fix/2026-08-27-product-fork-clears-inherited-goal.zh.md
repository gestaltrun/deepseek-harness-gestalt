# Agent Note: 产品级 fork 清除继承的目标

Status: implemented

[English](2026-08-27-product-fork-clears-inherited-goal.md) | 中文

## Problem

侧边会话由 `session.fork` 创建：子会话以父事件日志的前缀作种子。前缀中的 `goal/change` 事件折叠为子线程的当前目标，因此 fork 出的线程继承了父目标的一份完整副本——对 `get_goal` 可见、可被 `resume`/`complete`、并出现在目标 UI 中。[goal 领域持久事件](../architecture/2026-07-31-goal-owned-durable-events.zh.md) 决策曾把 fork 继承当作日志持久化的伴随后果接受，且续行停用已经阻止了自动继续。但侧边线程是一个新的并行人类线程，不是父目标的延续：无论是否启用续行，跨线程持有父目标的可变副本都是线程隔离缺陷。

## Decision

`GoalService.clearInherited(agent)` 是 fork 边界专属动词。宿主 `session.fork` 门面在子代理创建完成后立即调用它一次。该方法读取子会话持久的 `header.seedLength` 边界：当当前目标完全来自种子前缀、且子会话自身未追加任何 `goal/change` 时，向子会话自己的日志提交一条 clear 墓碑。墓碑保证清扫幂等——回放、后续恢复与重复调用都只读墓碑，绝不重复执行。已经自行变更过目标的子会话（resume、替换或清除过）保持自己的状态。

子会话发布后清扫失败时降级为继承视图并记录日志，而不是让 fork 失败：RPC 已提交子会话，对已发布会话报告 fork 失败会误报持久状态。

自动化种子路径不变：子代理 fork 提供方直接为子日志做种子，维持"继承后停用"姿态，因为自动化子代理永远不会像人类线程那样拥有父目标。

本决策收窄的持久化决策保持有效。会话日志仍是唯一持久权威，fork 继承仍是存储属性；产品级 fork 在创建时显式终止它。

## Alternatives considered

**从 fork 种子里过滤 `goal/change`。** 种子必须从 seq 0 连续；内部删除会破坏回放契约。在首个目标事件前裁剪不现实，还会隐藏会话历史。

**仅在 fork 时停用。** 即已发布的行为；它阻止了继续，却把目标留在子线程中可见且可变更，这正是被报告的缺陷。

**按谱系元数据在视图层掩盖目标。** 使日志与所有投影和工具读取产生分歧；为"该线程是否有目标"引入第二权威源。

**追溯补写已存在的 fork 会话。** 否决：清扫是创建时动词，为表现修复重写历史日志不成比例。记为 Known Limitation。

## Consequences

新 fork 的侧边线程以无目标状态开始，可以创建自己的目标；源线程的目标不受影响。`tool-goal` 的模型可见描述不变——其中关于 fork 的句子描述的是启用状态，对种子化自动化子代理仍然成立。已存在的 fork 会话继续显示继承目标，直到手动清除。包测试锁定墓碑、幂等性、所有权归属与无谱系情形；api-proxy fork 套件锁定门面清扫与源线程不受影响。
