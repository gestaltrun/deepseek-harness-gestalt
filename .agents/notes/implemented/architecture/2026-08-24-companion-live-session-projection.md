# Agent Note: Project live Sessions as bounded replacements

Status: implemented

English | [中文](2026-08-24-companion-live-session-projection.zh.md)

## Problem

The authenticated Companion product could load a Desktop-authoritative Session and refresh after a Mobile mutation, but an agent could continue producing committed output without another Mobile operation. The open transcript and hidden Session list therefore became stale until manual refresh or reconnect. Forwarding the raw Host event stream would expose process-local envelopes, require Mobile to reconstruct Host projections, and create an unbounded replay and compatibility surface.

## Decision

Encrypted Companion Protocol major 4 adds a pairing-scoped `observe-session` operation and an unsolicited `session-live` replacement. Each authenticated Mobile attachment observes at most one open Session. Desktop reads the current authoritative Host Session list and Workspace list for every changed Session, and reads bounded Session history only when that Session is open for the pairing. Hidden Session replacements contain only the summary, zero-based position after archived Sessions are filtered, and Workspace memberships. A missing authoritative Session produces an explicit removal. The protocol never forwards a raw Host event or a hidden transcript.

Every physical attachment completes an encrypted peer-offer exchange after Snow IK and before application data. Desktop includes its encrypted Companion offer in IK message 2 and retains a pending raw transport. Mobile opens that offer, sends its own encrypted offer as the next Relay ciphertext, and creates its codec after the send succeeds. Desktop creates its codec only after opening the Mobile offer, then publishes foreground synchronization. A deployment-configured positive deadline starts after IK2 is sent. Expiry cancels the raw Snow finalizer, clears the pending negotiation without publishing application authority, invalidates its pairing projection, and asks the existing Relay lifecycle to rebuild the attachment. Neither endpoint synthesizes the peer offer locally; an unsupported crossing releases the transport with the endpoint-specific `COMPANION_UPDATE_REQUIRED` or `COMPANION_SECURITY_CAPABILITY_MISSING` direction. The Relay client preserves that failure through the endpoint observer, and Mobile fail-closes its connection generation while the shared Web presentation identifies the endpoint that must update. A Platform capacity refusal delays attachment retry by the larger of server `retryAfterMs` and the local reconnect floor; the client schedules delays above one runtime timer in chunks, and the shared presentation displays the effective delay.

Desktop leases the current loopback Host's mux and Session WebSocket streams while authenticated Mobile connections exist. The first connection opens both streams and the last connection aborts them; Host replacement aborts the current pair before installing its successor. Authoritative Session events trigger one-Session projection. Workspace create, update, removal, reorder, and archive events trigger foreground synchronization followed by a complete paged baseline. The baseline filters `archivedSessionIds`, and its cursor owns a frozen Session and Workspace snapshot identified by pairing, physical generation, epoch, and offset rather than the Desktop revision assigned to each send. Model-visible `assistant/chunk` text is read only after it is present in durable Session history. Re-reading history keeps model-visible output reconstructable from the Session log rather than treating the transport frame as authority. Stream closure, invalid Host data, projection failure, or queue overflow retires the affected authenticated channel and asks the existing Relay lifecycle to reconnect.

One pairing-scoped source coalesces repeated changes by Session. Each observation change advances an epoch. Projection revalidates that epoch after the Host reads and immediately before Snow sealing; a stale detailed result becomes summary-only. Each attachment has a bounded queue of 32 distinct Sessions and one serialized Snow sender shared with operation results and foreground synchronization. The Desktop revision is allocated at encrypted send time and remains monotonic even when a failed send leaves a gap. A conversation that exceeds the complete 48 KiB projection limit drops oldest nodes first. If the latest node alone is oversized, its presentation text is truncated at a UTF-8 boundary to the largest encodable prefix. Every truncated conversation sets `hasMore`, preserving the `load-history` recovery entry from the oldest retained sequence. Mobile accepts a live replacement only for the current physical generation and a strictly higher revision. It ignores duplicates, replaces one Session atomically, and queues at most 32 distinct Sessions while the paged baseline is incomplete. A higher-revision foreground synchronization on the same physical channel starts a replacement baseline without rebinding the surface receiver, clearing operation correlation, or losing the observed focus and retained conversation. A completed baseline removes conversations for Sessions absent from its authoritative list. Only attachment replacement creates a new generation; transport events are not replayed.

Opening or closing the Mobile Session view sends the observation change. Previously authenticated content can remain visible while disconnected, but no observation crosses attachment replacement. Disconnect, background, pairing removal, Host replacement, or shutdown clears observers, pending projection work, WebSocket listeners, and abort controllers before releasing owned channels. Shutdown drains already-started ordered sends without accepting new work.

## Verification

Protocol tests pin encrypted peer-offer exchange, endpoint-specific cross-version and missing-security-capability rejection before application data, strict `observe-session` and `session-live` codecs, limits, removal fields, and revision fields. Desktop and Mobile unit tests pin negotiation expiry and timely completion, fake-timer capacity retry combination and long-delay chunking, Relay preservation and shared Mobile projection of update direction and localized capacity timing, open-versus-hidden projection, archive-filtered position, observation switch and close races, stream leases, coalescing, oversized single entries, cumulative transcript tails with `hasMore`, history recovery, generation replacement, same-channel baseline retention, teardown, duplicate revisions, bounded baseline merging, and shared-component observation lifecycle. The assembled test starts real Host Session persistence and HTTP/WebSocket streams, establishes the production Snow owner, pages more than 20 Sessions across changing send revisions, appends logged assistant chunks, and delivers a Workspace event baseline before a later Session creation while retaining the observed conversation. It also observes real Workspace reordering, removal, and Session archiving in the Mobile shared components. The keyless bundled Mobile build-and-preview snapshot shows the same visible transition, including the required Desktop upgrade state for a missing security capability, outside ports 5173 and 5174.

## Alternatives considered

**Poll or refresh after every visible interval.** Rejected because it adds idle traffic and still leaves an unbounded stale interval between polls.

**Forward raw Host events.** Rejected because Host events are not the Mobile presentation protocol, hidden Sessions must not receive transcript bytes, and transport delivery is not application authority.

**Send every full transcript.** Rejected because hidden Sessions need only bounded list state and a growing transcript would consume the interactive channel's fixed application ceiling.

**Persist and replay live transport frames.** Rejected because durable Session history already owns output. Reconnect obtains a new authoritative baseline and revisions provide connection-local idempotency.

## Consequences

An authenticated foreground Mobile view follows logged Desktop output without manual refresh, and its hidden Session list follows bounded authoritative summaries. The mechanism intentionally provides no background notification delivery and does not keep Mobile connected while backgrounded. A Host or projection failure temporarily trades liveness for an explicit channel reconnect and full resynchronization. Companion major 3 remains the immediately preceding safe version but cannot use live projection.
